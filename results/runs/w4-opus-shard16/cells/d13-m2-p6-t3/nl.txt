A network of vending machines runs a coordinator that pushes a shared price-update transaction to every machine using two-phase commit. In the first phase the coordinator asks each machine to prepare; each machine independently votes yes (it can apply the update) or no (it cannot). A machine may be slow, taking its time before voting, but no machine fails outright, so every machine eventually casts a vote. The coordinator collects the votes: only if every machine voted yes may it decide to commit; if any machine voted no it must decide to abort. Once a global decision is fixed it cannot change. After a commit decision each machine applies the update and moves to committed; after an abort decision each machine discards it and moves to aborted. A machine that has not yet voted, or whose vote has not been counted, is effectively a stale participant and must not have a committed outcome forced on it out of turn. Once every machine has finalised as committed or aborted, the coordinator starts a fresh round for the next price update. The core guarantee is that a machine reaches the committed outcome only under a genuine global commit decision in which every machine agreed.
SAFETY PROPERTY: No machine is ever in the committed state unless the global decision was commit and every machine had voted yes.
