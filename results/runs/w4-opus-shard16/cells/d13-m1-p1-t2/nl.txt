A network of vending machines keeps one shared inventory-count record for a product stocked across two independent operator instances; instance A owns two machines and instance B owns one, and all three sit on a single token ring. Exclusive write access to the shared record is granted by a single token that circulates around the ring: the token is passed from each machine to its ring successor. Any machine may at any time read the record and take a snapshot of its current version number. A machine may commit an update to the record only while it holds the token and only if its snapshot still equals the record's live version; committing advances the version by one and records the base version the update was built on. Because only the token holder writes and it must have an up-to-date snapshot, updates are serialised and none is silently overwritten. When the version reaches its cap the token holder may recycle the record back to a fresh baseline so counting can continue. However the token circulates and whichever machines read when, no committed update is ever lost.
SAFETY PROPERTY: The record's latest committed update was always built on the version immediately preceding the current one, so no update is ever lost.
