A container-ship crane yard keeps one shared stow-plan record that cranes revise as they work. The yard operates in epochs: a central hub advances to a new epoch whenever it reconfigures the fleet, and each crane remembers the epoch it last learned, catching up by adopting the hub's current epoch. The number of cranes allowed to hold a working reservation on the plan at the same time is a capacity that changes at runtime as cranes are added or withdrawn; the hub may grow or shrink this capacity. A crane whose known epoch is current may take a reservation as long as the capacity is not already full, and in doing so it snapshots the plan's current version number. A crane may commit a revision only while it holds a reservation and only if its snapshot still matches the plan's live version; committing advances the version by one, records the base version it built on, and releases the reservation. A crane may also release a reservation without committing. Because every commit must build on the version it snapshotted, no crane's revision is ever silently overwritten, regardless of how epochs advance or how the capacity changes.
SAFETY PROPERTY: The plan's latest committed revision was always built on the version immediately preceding the current one, so no revision is ever lost.
