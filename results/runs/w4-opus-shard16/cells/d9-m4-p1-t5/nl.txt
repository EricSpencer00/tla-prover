A power-grid load shedder maintains a shared load-setpoint record that many field producers want to update. Updates flow through a single bounded work queue with backpressure: a producer enqueues an update only while the queue has room, and when the queue is full producers are blocked. Each enqueued update is stamped with the setpoint version the producer observed when it created the update. A single consumer applies updates from the head of the queue in order. When it takes the head, the consumer applies it only if its stamped base version still matches the record's live version, in which case the setpoint advances by one and remembers the base it was built on; if the base is stale, meaning the version has moved since the update was created, the consumer rejects that head outright rather than letting it clobber newer state. A privileged grid administrator holds an override: the administrator may flush all pending updates and directly apply one authoritative setpoint change, bypassing the queue. Through backpressure, in-order application, stale rejection, and administrator overrides, no committed setpoint change is ever silently overwritten and lost.
SAFETY PROPERTY: The setpoint's latest committed change was always built on the version immediately preceding the current one, so no update is ever lost.
