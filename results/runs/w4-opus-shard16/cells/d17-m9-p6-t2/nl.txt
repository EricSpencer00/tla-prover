An airport baggage router is driven by two independent router instances that share one pool of sorting chutes. A central hub stamps the whole system with an epoch number and reconfigures to a new epoch whenever the layout changes, for example when a chute is remapped; reconfiguring retires the previous epoch and clears every chute back to inactive, since no chute is validly assigned under the new epoch yet. Each router node from either instance remembers the epoch it last learned and may catch up by adopting the hub's current epoch. A node may activate a chute for routing only while the epoch it knows matches the hub's current epoch; activating a chute stamps it with the epoch the activating node knew. A node that knows the current epoch may also deactivate a chute. The whole point of the epoch stamp is to keep a stale node, one still holding a retired epoch, from acting on the shared chute pool. The guarantee is that any chute that is currently active was activated under the hub's current epoch.
SAFETY PROPERTY: Every currently active chute carries the hub's current epoch as its activation stamp, so no stale node's activation is ever in effect.
